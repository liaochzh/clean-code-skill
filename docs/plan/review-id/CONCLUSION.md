## 结论（可用的三条）

1. **编号引用是真实能力，但不是稳定行为**。凡问题被判定为「规范异味」时几乎必带 `CleanCode/<家族>/<编号>`（fx1/fx3 多数轮次接近 100%；按统一口径复核 fx3-r2 为 67%）；一旦问题被判定为「行为/资金/边界 bug」，报告改用 `[Critical]/[High]` 严重度档，编号消失（fx4-r1 仅 2/8）——**编号率低 ≠ 不会引用，而是判为 bug 类时改用严重度标签**。
2. **植入项与编号的对应不总是唯一**。fx4 的复合条件植入（期望 G16）稳定被报为 F3/G23/N1；fx6 的 `max_score` 空列表（期望 T5）被报为 N4/「边界」。⇒ 后续复跑只比「该位置是否被报出 + 是否带任意合法编号」，不比「编号是否精确匹配」。
3. **超范围推断是主要噪声**，且与 fixture 类型无关（两轮各 1 次、集中在 fx1/fx2）。它不影响检出率，但会污染「事实性错误」指标；作为长期观测项保留。

## 退化判据（后续复跑用）

以 12 run 均值为比较单位：

- **告警**（任一满足）：
  1. 检出率 < 90%；
  2. 带编号条目每 run 均值 ≤ 1.0（基线 4.0 − 3）**且** 编号率 ≤ 42%（预登记：基线 62% − 20pp；同源集按统一口径复核为 64%，对应阈值 44%，仍按预登记的 42% 执行，宁可漏报不误报）——两条件同时满足才算退化，避免单一指标噪声误报；
  3. 某 fixture 连续两轮 0 编号（fx5 除外）；
  4. 事实性错误 > 8 条（基线 3 的 2.5 倍以上）。
- **不告警**：编号与期望值不精确匹配（见结论 2）；fx5 的 A1/A2 被报出但带「需核实」限定语。
- **比较前置**：`skillset sha1`（`d6d23a92…`，5 文件）与模板 sha1（`659da441…`）必须与基线一致；不一致则先判「规则改版」，重新建立基线而非报退化。

## system 硬化复测（r3 / r4，2026-10-27）⇒ **保留**

`system`（`opencode.jsonc:1277`「## 报告口径」段末）现行两句：

1. `证据必须落在被审范围内：分层关系、调用方是否存在、代码归属哪个文件、外部库或标准库是否存在，范围内无法证明的写成「待核实」的发现项，不得作为阻断项或结论依据。`
2. `待核实项每份最多 3 条，且不得用于范围内本可证实的事项。`

| 指标 | 基线（fx2–fx6 的 r2） | r3（句 1） | r4（句 1+2） | 判据 |
|---|---|---|---|---|
| 事实性错误（主判据） | 1 | **0** | **0** | 0 条 ⇒ 达成 |
| 检出 | 13/13 | 13/13 | 12/13（92%，fx5 的 A9 论点未命中） | ≥90% ⇒ 达成 |
| 编号率 | 64%（23/36） | 78%（28/36） | 59%（16/27） | ≥42% ⇒ 达成 |
| 待核实条目 | 4（行内限定） | 13（散落，单份最多 4） | 12（**独立成段，单份最多 3**） | 单份 ≤3 且独立成段 ⇒ 达成 |

**裁决**：r3 主判据达成但稀释护栏触发（13 条混在正式条目里）；追加句 2 后 r4 四项全部达成 ⇒ **保留，不回退**。新判据＝「事实性错误 0 条 + 检出 ≥90% + 编号率 ≥42% + 待核实单份 ≤3 且独立成段」。

**用户裁定（2026-10-27，纠正计数口径后复述代价）**：在知悉「r4 编号率 59% 低于基线 64%、也低于 r3 的 78%」的前提下，仍选**维持保留**——理由是本课题的目标是让断言可追溯，牺牲的编号率只影响「报告里贴了多少规则号」，而待核实稀释直接影响阻断项可信度。此裁定不是预登记判据的自动推论，故单列记录；若后续以编号率为第一目标，应改句 2 而非放宽判据。

**残余代价（记录，不触发回退）**：编号率 78% → 59%，**低于基线 64%**——句 2 把一部分判断从「带编号条目」降为「待核实附录」，等于用编号引用换确定性；fx5 的 A9「零使用抽象」论点在 r4 未被明确指出（仅按位置命中）。若后续要提编号率，方向是「允许把已证实的编号写进阻断项」，而不是放宽待核实口径。

**可复现性**：两轮各自独立复现「事实性错误 0」，`fx2` 的「标准库 `tax` 模块」这类硬错误不再出现，替代形态是「调用方是否已同步迁移：待核实」。

## 外部效度（2026-10-27 首版，见 `EXTERNAL.md`）

- **不能直接外推**，且原因不是「样本少」而是「对象不同」：12 份真实报告里只有 5 份可纳入（3 份配置/文档审、2 份代码·脚本审），**每层 n≤2**，按预登记判据只能判「样本不足」。
- 硬化前形态对照：真实样本带编号 **2/31**、待核实 **0**、范围外硬断言 **0**；合成基线对应 23/36、4、1。差距主因是对象类型分布（多数真实审的是文档/配置，本就不引 clean-code 编号）。
- **反直觉但重要的信号**：合成基线里 3 条事实性错误全部是「范围内无据的落点/库存在性断言」，真实样本 0 条。怀疑成因是**合成派单硬禁读跑、无文件路径**，而真实派单多有路径甚至允许读盘 ⇒ 「越范围断言」有相当部分是**测量方式诱发**的，不全是模型固有倾向。该假设本批无法证实，记入 `EXTERNAL.md` 待样本。
- 三条当前不可答：句 1/句 2 在真实任务的净效应；待核实 ≤3 在真实任务是否够用；A9 类断言的真实可达率（见下）。
