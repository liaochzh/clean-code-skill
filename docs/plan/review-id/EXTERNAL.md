# 外部效度台账（真实 review 报告，2026-10-27 首版）

> 本文件回答一个问题：合成夹具（fx1–fx6）得到的结论，能不能外推到真实 review？
> **首版结论：不能直接外推；本批只产出「硬化前形态对照」，前瞻部分靠台账累积。**

## 一、规则（先于读数，跑完不许改）

**纳入（宽松，用于回测）**：`docs/review/` 下由 review 子代理产出、含「审查范围」或可识别送审对象清单的报告（2026-10-28 起，已归集的基线样本在本仓库 `docs/review/`，新样本落在 `~/docs/review/`）。缺「执行模型」的按「未知」单列，不并入其它模型层。

**纳入（严格，用于台账）**：review 子代理产出 + 执行模型可读 + 有明确审查范围 + 计数区间不含主 agent 处置段。

**分层键**＝(产出 agent, Provider ID + Model ID, 审查对象类型)。层内 **n<5 只报绝对数**，不报百分率。

**计数口径**：沿用 `review-id/README.md`。条目＝报告内独立编号的发现项；带编号＝条目正文出现合法编号，**但**：

- **去碰撞规则**：仅当编号出现在 `[CleanCode/…]` 标签内或「依据／引用：」句中才计。若发现项序号与条目序列同构（连续、自 1 起、越过合法域上界如 `F5`/`F10`）⇒ 整份记「碰撞风险=高」，该份编号率只作参考。
- **计数区间**：只计「报告原文」段，主 agent 处置段（核销表／按反馈的修复／收尾处置）不计，逐份记起止行号。
- **硬断言**：无「待核实／需核实／若…则」限定却依赖范围外事实的结论条数。
- **待核实**：以「待核实／需核实／未经核实／无法证实」收束且未给确定结论的条目数。

**三值判据**：

| 值 | 条件 |
|---|---|
| 可外推 | 同层内与合成同模型读数差 ≤20pp，**且**形态一致（有无 `CleanCode` 标签、有无范围外断言） |
| 不可外推 | 同层读数差 >20pp，或形态相反 |
| 样本不足 | 层内 n<5 ⇒ 只报绝对数，不作任何外推判定 |

**固定不可外推清单**（无论样本多少都不外推）：检出率（真实样本无 oracle）、臆造计数、待核实上限（fx7 除外）、fx5/fx7 的期望命中。

**台账追加**：每份真实 review 落档后，派发方向本表追加 1 行（含 `_fingerprint.py` 的 `system_sha1`）。**复判触发点**（三选一即重算汇总）：累计 ≥5 份「system=后」样本 ／ `system_sha1` 变更 ／ 每月首周三。

## 五、判定与不可答项

**可外推**：无（层内 n<5）。
**不可外推**：① 检出率（真实样本无 oracle）；② 编号率的绝对水平（对象类型分布不同）；③ 待核实上限（真实样本全在硬化前）。

**三条当前不可答**：

1. **句 1／句 2 在真实任务上的净效应**——没有任何「后」样本。
2. **待核实 ≤3 在真实任务是否够用**——真实代码审样本只有 2 份，且都在硬化前。
3. **A9 类断言的真实可达率**——见 fx7 结论。

**一个值得注意的偏差信号**：合成基线的 3 条事实性错误全部属于「范围内无据的落点/库存在性断言」，而真实样本 0 条。可能原因是真实派单给了文件路径、允许读盘（3/5 允许 or 代跑），而合成派单**硬禁读跑**——即「越范围断言」部分是被测量方式诱发的。该假设不可在本批证实，记入台账待样本。
