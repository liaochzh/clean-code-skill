1. [High] dashboard_view.py:1,5-8 — 视图层直连数据库，违反模块自身契约与依赖规则
   - 触发条件：任何一次调用。文件 docstring 声明「只做展示，数据由调用方提供」，改动后 `render_dashboard(db_path)` 自行 `sqlite3.connect` 并执行 SQL，同时把参数契约从 `summary` dict 换成 `db_path`（破坏性签名变更）。
   - 依据：Clean Architecture 依赖规则（源码依赖必须指向内层；DB 是 Frameworks & Drivers 外层细节，视图不应知晓）、A10 架构漂移、SOLID-S（模块出现第二个变化理由：展示格式与存储方式）。
   - 影响：不可测（需真实库文件）、存储层不可替换、docstring 变成过时注释（C2 变体）、调用方若未同步改会直接坏。
   - 建议修正：数据获取上移到调用方/数据层，`render_dashboard` 恢复接收汇总值或 DTO；跨边界只传简单值对象。
   - 严重度：P1（本 diff 的核心变更方向，属回归）

2. [High] dashboard_view.py:7 — 空表边界：显示「总计：None」
   - 触发条件：`invoices` 表为空，或 `amount` 全为 NULL 时，`select sum(amount)` 返回 SQL NULL → Python `None` → 输出 `总计：None`。
   - 影响：面向用户的显示错误，且是首次部署/无数据时的常态路径，不是罕见分支。
   - 建议修正：`select coalesce(sum(amount), 0)`，或对 `total is None` 显式兜底。
   - 严重度：P1（正确性缺陷）

3. [High] dashboard_view.py:6-7 — 连接泄漏 + 异常无处理
   - 触发条件：正常路径 `conn` 从不 `close()`（每次渲染泄漏一个文件句柄）；异常路径（库文件不存在/损坏/表缺失）`sqlite3.OperationalError`、`fetchone()[0]` 结构假设均无上下文直接上抛。
   - 依据：错误处理「要么处理要么带上下文再抛」「不吞失败」；资源在 finally/退出时释放。
   - 建议修正：`with contextlib.closing(sqlite3.connect(db_path)) as conn:` 或 try/finally；按需包装异常并附 `db_path` 上下文。
   - 严重度：P1

4. [High] dashboard_view.py:11-12 — 金额用 float 乘法 + 税率魔法数字
   - 触发条件：任何非整 binary 可表示的金额，`amount * 0.0825` 产生二进制浮点误差（金额计算的舍入错误）；`0.0825` 无命名常量、无来源注释（州/市税率组合？）。
   - 依据：G25 魔法数字、魔法配置；金额精度属正确性而非风格。
   - 建议修正：`Decimal("0.0825")` + 明确舍入策略；税率提为 `TAX_RATE` 命名常量（或配置注入）。
   - 严重度：P1
