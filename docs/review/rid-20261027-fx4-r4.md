## 发现的问题

### 阻断交付

1. **[Critical] orders.py:8–11（`handle`）— 退款失败分支静默变成扣款**
   - 触发条件 A：`kind == "refund"` 且 `amount <= 0` → 条件不成立，落到 `charge(user_id, amount)`，以负数/零金额执行扣款。
   - 触发条件 B：`kind == "refund"` 且账户被锁（`locked(user_id)` 为真）→ 同样落到 `charge`：被锁账户本应拒绝退款，结果反被扣款。
   - 触发条件 C：任何拼错的 kind（`"refnd"`、`"Refund"` 大小写、`None`）→ 一律静默按扣款处理。
   - 影响：资金方向的语义颠倒，属财务数据错误/资损级缺陷，且无任何报错可供排查（违反「不吞异常 / 静默兜底」）。
   - 建议：退款条件不满足与未知 kind 应显式抛错（或返回失败结果）；`charge` 路径同样应校验 `amount > 0`。

2. **[Critical] orders.py:13–14（`export_invoice`）— 桩实现伪造成功**
   - 恒返回 `{"lines": [], "status": "ok"}`：不查 `self.repo`、不校验 `user_id`，任何输入都报 "ok" 且明细为空。
   - 触发条件：任何调用；调用方按 `status == "ok"` 消费时会拿到一张空发票并认为成功。
   - 影响：掩盖未完成/失败（静默兜底 + 假成功），是典型的「测试/下游被掩盖」级 P0；未完成就应显式失败（抛 `NotImplementedError` 或返回 `status: "error"`）。
