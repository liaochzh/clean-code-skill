## 发现的问题

### 缺陷类（review 口径）

- [High] storage.py:3,16-17 - 新增第三方依赖 `httpx_retry` 及 API `Retry(times=3).run(callable)` 均未经核实（clean-code A1 幻觉 API / A2 未核实依赖）。触发条件：包名拼错/不存在、或该库无 `Retry(times=...)` / `.run()` 接口时，`load()` 在 import 或调用时直接 ImportError/AttributeError；拼错的包名还存在 PyPI 抢注（typosquat）风险。影响：`load` 全部调用方（含既有直调路径）整体不可用。本次审查受「禁止执行命令」约束无法核实 registry 与已安装版本，该项必须在交付前由作者以源码/类型stub确认。
- [High] storage.py:15-17 - 行为变更（新增重试）无任何测试覆盖（T1/T5）。需覆盖：① 首次成功仅调用一次；② 瞬时失败后重试成功返回结果；③ 连续失败 3 次后异常向上传播（不吞错、不静默兜底）。影响：重试语义（times 是总尝试数还是重试次数、捕获哪些异常）无回归防护。
- [Medium] storage.py:16-17 - 重试配置不完整：无退避（backoff）、无超时（timeout）、未限定可重试异常类型。触发条件：下游持续故障或返回永久性错误（4xx/参数错）时，立即连发 3 次会放大故障流量（retry storm），且若 Retry 默认捕获所有 Exception 会掩盖编程错误。影响：可用性恶化、故障定位变难。
- [Medium] storage.py:6-7,10 - 新增 `Storage` Protocol 在本 diff 内无任何消费者：`load` 的参数 `client`/`key`、返回类型均未标注它，`FileStorage` 也未与之显式对齐（`read(self, key)` 无类型注解，与 `read(self, key: str) -> str` 契约脱节）。属"新建抽象无人引用"（A7 wiring 缺失）。
- [Low] storage.py:10-12 - 既有缺陷（非本 diff 引入，按范围纪律仅报告）：`open(key).read()` 未用 `with` 关闭文件句柄，异常路径下句柄泄漏依赖 CPython refcount。由于本 diff 以 Protocol 把该实现固化为 `Storage` 契约，建议顺带修复为 `with open(key) as f: return f.read()`。
