### 阻断交付（Critical / P0）

1. [Critical] orders.py:9-11 — **合法退款请求被静默转为扣款（资金错误）**
   触发条件：`kind == "refund"`、`amount > 0`，但 `repo.locked(user_id)` 为真。
   `if` 整体为假 → 落入兜底 `return self.repo.charge(user_id, amount)`。
   影响：用户发起退款，账户被锁定时代码不拒绝、不报错，反而**扣款**。退款失败路径必须 fail-closed（抛异常或返回明确错误），不得默认进入另一个资金变更分支。

2. [Critical] orders.py:9-11 — **负金额绕过 locked 检查**
   触发条件：`kind == "refund"`、`amount <= 0`（如 -100），无论锁定与否。
   `amount > 0` 不满足 → `charge(user_id, -100)`，负向扣款等效退款，**绕过 locked 门禁**；即使不传负数、仅传 0 也会打到 charge。金额合法性校验缺失且校验失败后的默认动作是资金变更。

3. [CleanCode/错误处理/A 家族-AI 伪实现] orders.py:13-14 — `export_invoice` 是无条件返回 `{"lines": [], "status": "ok"}` 的假实现
   触发条件：任何调用。
   影响：调用方拿到空发票却按 `status: "ok"` 视为导出成功——静默吞掉"未实现"这一事实，属"不吞异常/静默兜底"禁项的变体。
   建议：未实现应 `raise NotImplementedError`（或删除该函数，YAGNI），严禁硬编码成功状态。严重度 P0（若已有调用方）/ P1。
