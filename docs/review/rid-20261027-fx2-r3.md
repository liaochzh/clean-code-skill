### 阻断交付

1. [Critical] dashboard_view.py:7 — 空表/无记录时行为错误。
   - 触发条件：`invoices` 表存在但无行（或全部 amount 为 NULL）时 SQL `sum(amount)` 返回 NULL，`fetchone()[0]` 得到 `None`。
   - 影响：界面显示「总计：None」而非「总计：0」，属常见边界的可见行为错误。
   - 修法：`total = ... or 0`，或 `SELECT COALESCE(SUM(amount), 0)`。

2. [High] dashboard_view.py:6-7 — 未关闭连接、未处理任何数据库异常、`sqlite3.connect` 有隐式副作用。
   - 触发条件：① 每次调用都不 `close()`（视图函数反复调用即泄漏句柄）；② `db_path` 指向不存在的文件时 `sqlite3.connect` **不会报错，而是静默新建空库文件**，随后 `execute` 抛 `sqlite3.OperationalError: no such table: invoices`，异常裸传到展示层；③ 文件无权限/库损坏同理。
   - 影响：资源泄漏 + 展示层因未处理异常崩溃 + 视图函数在磁盘上凭空创建数据库文件（副作用不可见）。
   - 修法：`with contextlib.closing(sqlite3.connect(db_path)) as conn:` 或 `with conn:`；对可预期的失败（路径不存在、表缺失）在能做出决策的层级处理或带上下文再抛；可先用 `os.path.exists` 守卫。

3. [High] dashboard_view.py:1 vs 5-8 — 模块契约与依赖方向被改动破坏（CleanCode/架构/A10）。
   - 触发条件：docstring 声明「只做展示，数据由调用方提供」，但改动后 `render_dashboard` 自己连库、自己执行 SQL，展示层直接依赖最外圈的具体实现（sqlite3）。
   - 影响：① 顶层注释成为过时/误导注释（C2）；② 函数同时承担「取数」与「渲染」两个职责（SRP/G30），不可脱离数据库单测；③ 公开签名从 `render_dashboard(summary: dict)` 变为 `render_dashboard(db_path: str)`，是破坏性 API 变更——**调用方是否已同步迁移：待核实**（本次范围仅有单文件 diff，无法证明）。若任一调用方仍传 `summary` 字典，`sqlite3.connect(dict)` 直接抛 `InterfaceError`。
   - 修法：数据获取移出视图（调用方查好再传入 `summary`），或至少同步更新 docstring 并全量迁移调用方 + 补测试。
