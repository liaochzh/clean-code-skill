# clean-code

一个用于 **整洁代码规范** 的 agent skill：写码时当作规范参考，审查时当作检查清单。它不是审查流程，而是**判据库**——每条规则有编号、有严重度、有「什么时候可以不遵守」的分寸感说明。

> 面向 opencode / Claude 一类支持 `SKILL.md` 的 agent 运行时。纯提示词实现，无依赖、无脚本、不联网也能用。

## 它解决什么问题

| 常见失败 | 本 skill 的做法 |
|---|---|
| 原则背了一堆，落到具体代码上还是「看感觉」 | 每条原则配**实践测试**（能不说 "and" 就描述职责吗？改一处另一处是否必然跟着改？）|
| 把「整洁」当成教条，给一次性脚本上全套基线 | **分寸感**一节按「寿命 × 爆炸半径」分四档力度，偏离原则时要求能说出理由 |
| 报告里大段复述定义，读者抓不住重点 | **规则编号**：C/F/N/G/T/A 六族 + P0/P1/P2 严重度，报告只写「编号 + 名称」 |
| DRY 理解成「长得一样就合并」 | 明确 **DRY 管的是知识不是字面**，用「改一处另一处是否必然跟着改」判定真假重复，并提出三次法则 |
| 审 AI 生成的代码时，常规规则套不上 | 单列 **A1–A10**（幻觉 API、防御性冗余、注释重复代码、过度抽象、伪通用等）|

## 何时触发

用户说「按 clean-code 审一下 / 这代码整洁吗 / 重构一下 / 有没有代码异味」，或需要一份带编号与严重度的代码质量结论时。

**不适用于**：实施前的方案/设计文档评审（用 `design-review`）、skill 或代码的安全性审计（用 `skill-auditor`）、Bug 根因定位（用 `debug`）。`description` 里已写明这些排除关系。

## 安装

```bash
# 方式一：整个目录放到 skills 根目录
git clone https://github.com/liaochzh/clean-code-skill.git
cp -R clean-code-skill ~/.config/opencode/skills/clean-code

# 方式二：软链（便于跟随仓库更新）
ln -s "$(pwd)/clean-code-skill" ~/.config/opencode/skills/clean-code
```

不同运行时的 skills 目录不同（例如 Claude Code 的 `~/.claude/skills/`），把本目录放进去即可，`SKILL.md` 的 frontmatter（`name` / `description`）就是触发依据。

## 结构

```
SKILL.md                              # 主体：核心原则 → 分寸感 → 命名/函数/注释/格式化/结构
                                      #       → 错误处理/对象/类与模块/并发 → SOLID
                                      #       → 规则编号与严重度 → 异味与反模式 → A1-A10
                                      #       → 测试 → 编辑前检查 → 自检清单 → NEVER → 应用顺序
references/solid-and-architecture.md  # 按需读：SOLID-S/O/L/I/D、依赖规则、四层职责、CCP/CRP/SDP/SAP
```

`SKILL.md` 约 24 KB（496 行），`references/` 引用只一层深。

## 规则编号速查

| 家族 | 覆盖 |
|------|------|
| `C1-C5` | 注释：元数据、过时、冗余复述、注释掉的代码 |
| `F1-F4` | 函数：参数过多、出参副作用、布尔 flag 参数、死函数 |
| `N1-N7` | 命名：描述性、行业惯用词、无歧义、无类型编码前缀 |
| `G1-G36` | 通用：DRY、死代码、意图被遮蔽、多态替代类型分支、魔法数字、迪米特法则 |
| `T1-T9` | 测试：覆盖、边界、速度 |
| `A1-A10` | AI 生成代码特有异味 |

严重度：**P0 阻断**（行为错误、数据丢失、安全漏洞、吞掉失败、弱化测试）、**P1 应修**（让下一次改动不安全）、**P2 建议**（抬高每次改动成本）。

## 设计要点

- **规范不是流程**：本 skill 只提供判据；谁加载、何时加载、怎么落报告，由 `build` / `review` 各自的编排决定。
- **可引用性优先**：规则编号稳定、定义单一真源（编号表只在一处），报告里只写编号 + 名称，避免同一规则在不同章节出现两份措辞。
- **分寸感前置**：先判寿命与爆炸半径，再决定力度——这是与「机械套规则」最主要的区别。
- **不越界**：明确不承担方案评审与安全审计，避免 skill 之间职责重叠。

## 关于效果验证

作者的本地验证集（fixtures / oracle / 逐轮读数）不随仓库发布：其中含本地绝对路径与门禁内部细节，且部分结论依赖当轮的 agent 配置指纹，跨版本不可复现。仓库只放 skill 本体。
